electron-build-slim

Ship smaller Electron apps without touching how they run. A drop-in replacement for the electron-builder command that packages only the node_modules your app actually loads.

npm GitHub Releases Benchmark data

Quick start

npm i -D electron-build-slim
npx electron-build-slim --win          # instead of: electron-builder --win

Your electron-builder config stays where it is. Arguments pass straight through; the tool only appends files exclusions and size settings, then checks that the packaged app can still load every dependency it shipped.

What it removes, and what it never touches

Removed by default

Dependencies the app never loads (often the electron npm package itself, pulled in as a peer), build-only tools like node-gyp, docs/tests/C++ sources inside packages, and native binaries for other platforms.

Opt-in

Chromium locales (--slim-languages) and Windows WebGPU-only DLLs (--slim-strip-webgpu). These can change behavior, so you decide.

Never

Compression changes for formats that decompress at every launch (AppImage, snap), asar: false, UPX, or deleting Chromium runtime files.

Verified

After each build the packaged Electron runtime loads every shipped dependency. A missing file fails the build. If electron-builder fails, the tool cache is refreshed and the build retried once.

Lessons from the benchmark

  • Apps whose own config already ships only what they need (Pear Desktop, Super Productivity) gain almost nothing by default. Apps that ship whole dependency trees gain the most.
  • A renderer with nodeIntegration can load packages with window.require(). LosslessCut does; the tool now keeps explicit require("…") calls found in the renderer.
  • Some apps disable the RunAsNode fuse; the smoke check runs a temporary copy with that fuse on.
  • Removing locales changes app.getLocale() and navigator.language, so apps that pick their language from it start in a kept language.
