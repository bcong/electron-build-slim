Leftover-file cleanup for Electron builds

A drop-in replacement for the electron-builder command. Your config stays as it is; the tool leaves out the node_modules and files your app never loads, then starts the packaged app to check nothing it needs went missing.

On 10 open-source apps the unpacked build shrank by 0.0% to 20.7%, and every one opened to the same first screen.

Install from npm See the benchmark
your-app
$ npm i -D electron-build-slim
# see what would be kept and dropped
$ npx electron-build-slim plan --win
# build, in place of: electron-builder --win
$ npx electron-build-slim --win
# size of app.asar per package
$ npx electron-build-slim report dist/win-unpacked/resources/app.asar

Savings depend on what your build ships. Some projects save nothing.

This package does not shrink every Electron app. It removes what is left behind in the package without being used: dependencies the app never loads, build tools, docs and tests inside packages, and binaries for other platforms.

It does not optimize or compress the code and assets your app needs, and it never trades a working feature for a smaller file. If your build already ships only what it uses, the size stays about the same; Pear Desktop and Super Productivity below saved 0.0%.

Removed when unused

  • Dependencies the app code never loads, often the electron package itself
  • Build-only tools such as node-gyp and prebuild-install
  • Docs, tests and C/C++ sources inside packages
  • Native binaries for other operating systems and CPUs

Left as it is

  • Every package the app loads, and the files inside it that run
  • Chromium runtime files, unless you opt in to dropping locales or WebGPU DLLs
  • Your electron-builder config and hooks
  • Startup speed: no UPX, no slower AppImage compression

What runs by default, what you switch on

Default

Unused dependencies, build-only tools, docs, tests and C/C++ sources inside packages, and native binaries for other platforms are added to electron-builder's files exclusions. Installer compression goes from store to normal.

Opt-in

Chromium locales with --slim-languages and Windows WebGPU-only DLLs with --slim-strip-webgpu. Both can change how the app behaves, so the tool never turns them on for you.

Never

Slower compression for formats that unpack on every launch (AppImage, snap), asar: false, UPX, or deleting Chromium runtime files such as icudtl.dat and *.pak.

After every build

The packaged Electron runtime loads each shipped dependency, and a missing file fails the build. If electron-builder itself fails, the tool cache is cleared and the build runs once more.

Install and keep your config

Arguments pass straight through to electron-builder. The tool appends exclusions and size settings and never rewrites your config file.

npm i -D electron-build-slim
yarn add -D electron-build-slim
pnpm add -D electron-build-slim
# GitHub Packages, needs a token with read:packages
echo "@bcong:registry=https://npm.pkg.github.com" >> .npmrc
npm i -D @bcong/electron-build-slim

Node.js 20.12 or newer, electron-builder 23 to 26, npm, yarn and pnpm. Run report on your current build first: if it lists node_modules/electron, node-gyp or renderer libraries like react, there is something to remove. If it does not, expect little change.

Findings from the benchmark

  1. Tidy configs gain littlePear Desktop and Super Productivity already ship only what they need. Apps that ship whole dependency trees gain the most.
  2. Renderers can load packages tooLosslessCut loads packages with window.require() from a nodeIntegration renderer, so explicit require("…") calls there are kept.
  3. Some apps turn off RunAsNodeThe smoke check runs a temporary copy with that fuse on, so it works on those apps as well.
  4. Fewer locales change the app's languageDropping locales changes app.getLocale() and navigator.language, which is why it stays opt-in.
